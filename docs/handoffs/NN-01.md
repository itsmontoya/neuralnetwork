## Ownership and supported cases

The design specifies private owned float32/int64 storage; copied shapes,
constructors, accessors, and cloning; concrete nonnegative int64 dimensions;
checked allocation/index arithmetic; rank-zero scalars; zero-element values;
and disjoint caller-owned destinations. Shallow Tensor copies share storage
identity and must be detected as destination aliases, including empty tensors.
All argument validation precedes destination writes. Published inputs and
statistics are read-only by contract, and shared readers require no shared
scratch. Concurrent callers need disjoint outputs and immutable shared inputs.

The initial matrix/activation bridge copies and preserves existing APIs.
Nonempty product accumulation follows the existing float32 matrix path.
Zero-sized tensor operations avoid invalid positive-size matrix construction.
No ONNX wire/version/symbolic metadata types, training state, graph executor,
public views, or mutable backing slices enter the tensor contract.

## Dependencies and limitations

NN-02 must implement the storage signatures and NN-03 the shared checked shape
machinery before later kernels use them. Each kernel task adds its own shape
planners and numerical fixtures. The document identifies reference-dependent
nonfinite/empty-reduction behavior for those tasks to finalize explicitly.
It does not claim numerical conformance from written signatures alone.

RT-01 is unimplemented; the local ONNX roadmap proposes IR 8/opset 13 and ONNX
v1.16.2 but has not pinned its profile/reference tools. The runtime must supply
schema defaults, allocation budgets, graph/session ownership, and cancellation
between these synchronous kernels. Kernels initially have no in-loop context
checks. NN-13 requires the unavailable RT-12 working runtime and measured graph
benchmarks; zero-copy bridges, public workspaces, and packing remain later work.

## Changed files and API

`tensor/shape.go` and `tensor/broadcast.go` add the contracted public APIs:

```go
func ValidateShape(shape []int64, dataType DataType) (elements, bytes int64, err error)
func NormalizeAxis(axis int64, rank int) (normalized int, err error)
func BroadcastShape(left, right []int64) (shape []int64, err error)
func ValidateBroadcastTo(source, destination []int64) (err error)
```

`tensor/shape_size.go` factors shared checked arithmetic used by storage and
shape planning. `tensor/indexing.go` adds private strides and offsets.
`tensor/shape_test.go` and `tensor/indexing_internal_test.go` test the public
contracts and private boundary arithmetic. `docs/tensor-design.md` records the
implemented shape subset and its empty/size policy. No existing matrix, layer,
training, serialization, or Tensor public signature changed.

Later kernels and their planners must reuse these private helpers:

- `validateShapeSize(shape, dataType)`: selected-type element/byte validation,
  shared with `ValidateShape` and the existing Tensor constructors/validation.
- `validateDimensions(shape)`: checks every nonnegative host-representable
  dimension and reports whether any is zero.
- `checkedProduct(dimensions)`: host-representable product; the empty list
  produces one. Every dimension is validated before a zero-containing list
  returns zero, without multiplying unused nonzero dimensions.
- `checkedAdd(left, right)` and `checkedMultiply(left, right)`: nonnegative
  host-representable operands/results. They reject negative operands, even
  when multiplication would otherwise produce zero. Convolution and pooling
  geometry must first check nonnegative extents, then handle signed differences
  explicitly; these helpers do not implement signed arithmetic or floor/ceil.
- `contiguousStrides(shape)`: owned row-major int64 strides with every used
  suffix product checked. It rejects an unrepresentable suffix even when an
  earlier dimension is zero.
- `shapeOffset(shape, indices)`: exact-rank nonnegative coordinates, checked
  strides/products/sums, and a checked host-int offset. Scalars accept an empty
  index list and return zero; empty tensors have no valid element coordinate.
- `shapesEqual(left, right)`: exact dimensions/rank; nil and empty shape lists
  both denote the same rank-zero scalar shape.

`dataTypeByteSize` remains the private storage-width helper from NN-02.

## Ownership and supported cases

Shape helpers allocate no numeric payload and never mutate shape arguments.
Broadcast result shapes and private stride results are owned copies. There is
no new view, public workspace, destination mutation, or global mutable state.
Calls with immutable shared shapes may run concurrently.

`ValidateShape` supports both storage types and retains NN-02 scalar/empty and
checked-allocation behavior. A nil/empty shape has one element. A concrete zero
dimension has zero elements but cannot hide an invalid dimension. Checked sizes
do not impose a physical-memory budget.

`NormalizeAxis` accepts `-rank <= axis < rank` only for positive ranks; it checks
the range before normalizing negative values. Flatten's endpoint split axes and
Unsqueeze's output-rank policy remain their own operation-specific tasks.

Broadcasting aligns trailing dimensions, treats absent dimensions as one, and
requires equal dimensions or a one. Thus zero with one produces zero, while
zero with two fails. Scalar operands, channel bias, expanded multiple axes,
different ranks, and empty outputs are supported. The two broadcasting APIs
validate float32 payload representability for numerical callers, including the
derived result. `ValidateBroadcastTo` additionally rejects extra source axes
and any enlargement of the given destination, as Gemm bias requires.

An empty shape can remain valid storage while a requested suffix stride cannot
be represented. Empty kernels should validate operation arguments and then
skip unused indexing plans. Every stride actually requested is checked.
Kernel-specific destination/type/alias validation arrives with NN-04; these
shape-only functions perform no writes to tensor payloads.

Broadcast tests use explicit expected mathematical shapes, checked against the
rules in the [ONNX broadcasting documentation](https://onnx.ai/onnx/repo-docs/Broadcasting.html).
They are not numerical conformance fixtures or a finalized runtime opset claim.

## Dependencies and limitations

NN-04 through NN-12 add their numerical kernels and operation-specific planners
using this shared arithmetic. No kernel or ONNX schema/default handling is
implemented by NN-03. Symbolic dimensions, runtime limits, and graph/session
execution remain the separate runtime's responsibility.

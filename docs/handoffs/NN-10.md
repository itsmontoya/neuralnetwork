## Ownership and supported cases

All inputs/destinations are float32 NCHW rank-four values. Kernel extents,
strides, and dilations are positive; pads are nonnegative top/left/bottom/right
values. Configs have no schema defaults and their zero value is invalid.
Maximum pooling accepts dilation; average pooling requires `[1,1]` dilation.
Global averaging returns `[N,C,1,1]`. Automatic padding and schema/profile
restrictions belong to the runtime adapter.

Shape planning returns copied metadata without numeric payload allocation.
All tensors, dimensions, type/shape contracts, configuration, maximum sampling
coordinates, derived sizes, and storage identities are validated before writes.
Returned errors preserve the destination. Pointer and shallow-copy destination
aliases are rejected, including empty values. Input values remain unchanged.
Caller-owned outputs survive later calls; shared immutable inputs are safe
across calls with disjoint destinations. There is no retained scratch, argmax
history, optimizer parameter, backward cache, or mutable global state.

The loops adapt the existing layers' NCHW window traversal without constructing
layers. Only valid input samples are visited, so padding does not require a
materialized tensor or iteration over absent samples. Maximum pooling excludes
padding and starts with negative infinity. A window without input samples
produces negative infinity; input NaNs propagate. Average pooling sums float32
values in row-major order and uses either the full kernel area or the actual
input sample count. Zero-divisor averages and global zero-spatial reductions
produce NaN. Full-kernel all-padding averages produce zero. Finite comparisons
use `atol=rtol=1e-5`; NaNs compare by classification and infinity signs exactly.
Max-zero tie signs and NaN payloads are not cross-backend guarantees.

No max indices or storage-order argument is provided. The runtime must reject
indices outputs and nondefault storage order instead of fabricating them.
Nonempty average calls require a host-representable kernel area, even for a
clipped giant kernel. Empty outputs skip that unused product only after all
arguments, configuration, and aliases have been validated.

## Checked geometry and contract correction

Private `spatialExtents` validates host-representable nonnegative dimensions,
positive kernel/stride/dilation, effective kernel `(kernel-1)*dilation+1`, and
padded extent using the shared checked arithmetic. `spatialOutputDimension`
continues providing floor geometry for both convolution and pooling.
`poolOutputDimension` adds exact integer ceil geometry, including negative
numerators, and caps output by the number of starts below `input+beginPad`.
This removes trailing starts arithmetically, without a potentially huge loop.
`validateSpatialCoordinates` checks the largest padded sampling sum, including
ceil windows beyond padded extent, before subtraction or host conversion.

Private `poolKernelRange` requires this checked geometry and returns valid
kernel-index bounds. Its signed difference is bounded by checked
`input+beginPad`. The pooling value helpers require already validated nonempty
outputs; average kernel-area validation bounds both divisor products.
Later kernels should keep reusing shared `checkedProduct`, `checkedAdd`,
`checkedMultiply`, `validateTensorType`, and `validateDestination`.

NN-10 corrects NN-01's unverified declared-padding-only average divisor.
Executed ONNX 1.16.2 and ONNX Runtime 1.19.2 both divide by the full kernel
area when CountIncludePad is true, including partial ceil windows beyond
declared padding. For input 1 through 9 shaped `[1,1,3,3]`, kernel/stride
`[2,2]`, no pads, and ceil mode, included averages are
`[3,2.25,3.75,2.25]`; excluded averages are `[3,4.5,7.5,9]`.
Tests assert those literal results and divisors. Public signatures are unchanged.

The task-required ceil trimming is preserved. In the explicit `[1,1,3,3]`
input, `[3,3]` kernel/stride, `[0,0,2,2]` padding case, ORT returns `[2,2]`
spatial output for max and both averages while the library trims to `[1,1]`.

ORT uses the lowest finite float32, while the library uses negative infinity.
ORT rejects the other 21 cases because padding must be smaller than kernels,
only N may be zero, or raw output extents are negative. These mathematical
library extensions and disagreements are documented limits, not universal
ONNX conformance claims. The fixture README links exact primary sources.

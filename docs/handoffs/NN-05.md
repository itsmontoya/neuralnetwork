## Ownership and supported cases

All numerical inputs and destinations require float32. MatMul supports dot
products with scalar output, matrix/vector combinations, rectangular matrices,
and trailing-axis batch broadcasting. Scalar operands fail. Empty contractions
produce exact positive zeros without constructing zero-size matrices. Empty
outputs validate every argument and then skip unused block/stride arithmetic,
including large metadata-only prefixes that would not fit a numeric payload.
Actual input and output element/byte sizes always remain checked.

Gemm requires rank-two A/B, applies both explicit transpose flags, and supports
optional scalar, vector, row, column, or full bias via unidirectional
broadcasting. Config coefficients have no implicit defaults; their zero value
means Alpha=Beta=0. Finite and nonfinite float32 coefficients are accepted.

To match the pinned ONNX reference, Beta equal to positive or negative zero
skips bias arithmetic even if the bias contains NaNs/infinities. Every supplied
bias is nevertheless validated, and its destination alias is rejected. Alpha
always scales the computed product, including a zero/nonfinite product. Nil
bias omits its term and ignores Beta. These choices clarify the mathematical
formula rather than importing schema/version/default types into the library.

Constructors, accessors, shape plans, and kernels preserve input ownership.
Pointer and shallow-copy storage aliases are rejected as destinations, including
empty tensors and zero-coefficient calls. Repeated read-only inputs are valid.
Nonempty batch products use call-local output storage and copy back only after
all adapters succeed, so returned errors leave the destination unchanged.
Independent calls share no mutable scratch; outputs survive later calls.
Dynamic weights and immutable initializer weights use identical APIs.

Later tasks can reuse private `matrixProductValues` for already validated
nonempty rank-two float32 blocks and private `broadcastDimensions` for checked
dimension-only metadata. Callers of the latter must validate actual numeric
shapes themselves. Existing checked shape, stride, type, and destination helpers
remain the shared foundation. No borrowed view/public workspace is introduced.

## Dependencies and limitations

The copying bridge intentionally allocates temporary matrices and call-local
output storage. Runtime budgets must include those copies; NN-13 needs real
runtime measurements before changing ownership. No packing, public bridge,
workspace, in-loop cancellation, integer product, graph execution, or schema
default is added. The pinned fixtures cover selected library cases; RT-01
still owns its runtime profile and general conformance is not claimed.

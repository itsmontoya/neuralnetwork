## Changed files and API

`tensor/arithmetic.go` implements the contracted APIs:

```go
func AddInto(left, right, destination *Tensor) (err error)
func SubInto(left, right, destination *Tensor) (err error)
func MulInto(left, right, destination *Tensor) (err error)
func DivInto(left, right, destination *Tensor) (err error)
```

`tensor/destination.go` supplies private shared argument/destination validation.
`tensor/arithmetic_test.go` covers numerical fixtures, validation, ownership,
concurrency, and existing matrix division compatibility. `tensor/testdata/`
contains the original fixture generator, reference/provenance documentation,
and offline expected values. `docs/tensor-design.md` records the shipped subset.
Existing matrix, layer, training, serialization, and Tensor signatures remain
unchanged. No Go module dependency was added.

Later tasks should reuse these private helpers:

- `validateTensorType(name, value, dataType)` validates nil/zero/storage/type
  before access, returning argument context.
- `validateDestination(destination, dataType, shape, inputs...)` checks exact
  type/shape and rejects shared storage identities, including empty/shallow
  copies. Inputs must already be validated; nil optional inputs are ignored.
- `binaryFloat32Into(left, right, destination, operation, matrixOperation)`
  performs all operand/broadcast/destination validation, skips unused plans for
  empty output, then selects the optional matching-shape matrix adapter or the
  broadcast loop. NN-12's Pow can use a float32 operation and nil matrix adapter.
- `broadcastFloat32Into` is the internal loop for already validated nonempty
  float32 operations. It finishes all stride planning before writing.
- `broadcastStrides(input, output)` validates unidirectional broadcasting and
  returns aligned input strides with zero on expanded axes. It is intended for
  nonempty plans only; empty kernels must skip unused indexing plans.

These helpers reuse NN-03's checked shape/stride arithmetic. Each nonempty input
has validated host-representable storage and contiguous strides; output
coordinates either select an in-range input coordinate or a zero stride. Thus
loop offsets and their host-int conversions remain bounded by the validated
input lengths. No unchecked shape products or new allocation policy is added.

## Ownership and supported cases

All kernels require float32; unsupported integer operands/destinations fail
explicitly, even for empty values. They support arbitrary compatible ranks,
scalars, residual shapes, channel bias, multiple broadcast axes, and empty
results. `BroadcastShape` remains the output planner. Broadcasting never expands
a full input copy. Matching nonempty shapes for Add/Sub/Mul use local copying
adapters around existing matrix destination operations, flattened to one row.
Matrix results are copied to the tensor only after every adapter call succeeds.
Div always uses float32 division because matrix division rejects zero.

Inputs remain unchanged. Destinations must be disjoint from every input by
private storage identity; repeated read-only inputs are allowed. Validation,
alias checks, and index planning precede destination writes. Validation errors
preserve destinations. Empty results validate every argument and alias rule,
then skip unused strides, including otherwise unrepresentable suffix products.
There are no borrowed views, hidden global scratch, or retained outputs.
Disjoint calls can read shared immutable inputs concurrently, and later calls
cannot overwrite an earlier destination unless the caller explicitly reuses it.

Float32 division follows ordinary IEEE arithmetic: signed nonzero/zero gives
signed infinity; zero/zero and infinity/infinity give NaN; finite/infinity gives
signed zero. Add/Sub/Mul retain the corresponding float32 behavior. Exact NaN
payloads/signs are unspecified. Every selected finite result, infinity, and
signed zero matches the pinned fixtures bit for bit on the tested paths.

## Dependencies and limitations

NN-05 through NN-12 can reuse the destination and broadcast helpers without
adding mutable initializer access. Matrix copying costs remain intentional
until NN-13 has working-runtime measurements. No new public workspace, integer
arithmetic, cancellation, schema default, or ONNX graph behavior is implemented.
The selected reference version pins these tests; RT-01 still owns the runtime's
profile, and these fixtures do not imply general ONNX conformance.

## Ownership and supported cases

Input and output use float32 NCHW `[N, C, H, W]`. Weights use
`[M, C/Groups, kH, kW]`, unlike the existing layer's `[C*kH*kW, M]` matrix.
Optional bias is exactly `[M]`; nil omits it. The direct loop adapts the
existing layer's cross-correlation indexing to this weight order, independent
dilation/strides, and group-local input channels. No weight packing is needed.
Depthwise convolution includes channel multipliers; dynamic and constant
weights have identical library behavior.

Groups, C, M, kernel extents, strides, and dilations must be positive. Groups
divide C and M, and weights must have exactly C/Groups channels. Pads are
nonnegative in top/left/bottom/right order; schema defaults and automatic
padding remain the runtime's responsibility. Zero config is invalid.
Floor geometry is `max(0, floor((input + begin + end - effective)/stride)+1)`,
with effective kernel `(kernel-1)*dilation+1`. Oversized kernels produce empty
spatial outputs. Zero batches/spatial extents are valid; sufficient padding
can produce bias-only output even when an input spatial dimension is zero.

All tensors, dtypes, dimensions, optional bias, output sizes, configuration,
coordinate bounds, and destination storage identities are checked before
writes. Errors preserve the destination. Pointer and shallow-copy aliases
with input, weights, or bias are rejected, including empties. Inputs may
alias other read-only inputs. Shape planning returns copied metadata without
numeric allocations, and empty calls skip otherwise unused iteration spaces.
Outputs remain caller-owned and independent of subsequent calls.

No optimizer parameters, gradients, backward caches, packed weights, numeric
scratch, retained outputs, or hidden global state are constructed. Independent
calls may share immutable input/weights/bias with disjoint destinations.

## Shared geometry handoff

NN-10 should reuse private `spatialOutputDimension` for floor geometry or
narrowly extend it for ceil geometry, and reuse `validateSpatialCoordinates`.
The first validates all dimensions/configuration as host-representable,
checks positive kernel/stride/dilation, and uses shared `checkedMultiply` and
`checkedAdd` for effective kernel, padded extent, and output size. Negative
numerators are handled before division so Go truncation cannot replace floor.

`validateSpatialCoordinates` requires validated nonnegative output and positive
kernel/stride/dilation. Zero output returns immediately. Otherwise it checks
`(output-1)*stride + (kernel-1)*dilation` before any sample coordinate is used.
This also serves future ceil windows extending beyond declared padding.
Subtracting a nonnegative host-representable begin pad from a checked padded
coordinate then remains signed-host-representable. Valid input coordinates
and validated payload lengths bound all loop offsets and int conversions.

Later kernels should continue reusing `ValidateShape`, `checkedProduct`,
`checkedAdd`, `checkedMultiply`, `validateTensorType`, and
`validateDestination`. Private convolution loop helpers require the validated
nonempty caller path and are not general geometry APIs.

## Dependencies and limitations

These APIs implement mathematical float32 NCHW 2D cross-correlation, not ONNX
schema validation. General ranks/layouts, automatic padding resolution, public
views/workspaces, constant packing, device coherence, and in-kernel
cancellation are outside this task. NN-13 still requires runtime measurements
before ownership/bridge optimizations. No ONNX module import is added.

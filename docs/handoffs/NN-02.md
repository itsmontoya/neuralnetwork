## Ownership and supported cases

Constructors own copies of shape and typed payload. `New` zero-fills exactly
one selected storage type. Accessors and `Clone` copy; no mutable backing slice,
generic value constructor, or numeric conversion is exposed. Integer values
above `2^24`, including both int64 extrema, remain exact. Float32 copies preserve
signed zero, infinities, and NaN bit patterns.

Nil/empty shapes are one-element scalars; shapes with a zero dimension are
zero-element concrete values. Every dimension is checked before the zero-size
short circuit. An empty value may contain large host-representable dimensions
without materializing unused products. Negative and non-host-representable
dimensions are rejected even in empty shapes. Nonempty element and byte products
must fit both int64 and host `int`. Typed storage-length errors are detected
before allocating the payload.

Each Tensor owns a private nonzero-sized `*byte` identity. A shallow Go copy
retains that identity and numeric storage; independent constructors and clones
receive distinct identities, including empty tensors. Later destination kernels
must compare these identities to enforce alias rejection. `Clone` also owns an
independent shape. Shared published inputs are read-only by contract; there is
no global mutable state or public mutation API in this task.

Nil and zero-value tensors are invalid. Validation, typed access, and cloning
return errors. Metadata methods return Invalid/nil/zero for invalid receivers;
use `Validate` or `DataType` to distinguish those from valid scalar/empty values.
`ByteSize` counts numeric payload only, excluding metadata/allocation overhead.

## Dependencies and limitations

NN-03 adds the public shape-only planners and shared indexing/broadcast rules.
No kernel, public shape planner, public workspace, borrowed view, or matrix
bridge is added here. Checked representability does not impose an allocation
budget or guarantee that representable allocations fit physical memory; runtime
limits must be applied before allocation. Later empty operations must check any
strides/offsets they actually use rather than assuming unused products fit.

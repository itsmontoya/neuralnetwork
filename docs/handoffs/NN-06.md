## Ownership and supported cases

Every kernel requires float32 input and destination with identical shape.
ReLU, Sigmoid, and Tanh support arbitrary ranks, including scalars and empty
values. They copy nonempty values through existing `activation` implementations
using a local `[1, elementCount]` matrix adapter; only successful adapter results
are copied into the destination. No layer, optimizer, or backward cache is
constructed.

Softmax accepts a resolved axis in `[-rank, rank)` and rejects scalars. It
uses checked outer/axis/inner geometry for stable maximum-subtracted float32
normalization, including logically noncontiguous first and middle axes. The
disjoint destination holds exponentials until each logical slice is normalized;
all intermediate state belongs to the invocation. No hidden shared scratch or
public workspace is introduced.

All tensor, shape, dtype, axis, alias, and derived-size validation precedes
writes. Returned errors preserve destinations. Pointer and shallow-copy storage
aliases are rejected, including empty values. Empty tensors succeed only after
validation, and skip unused products so large otherwise valid empty dimensions
do not require representable nonempty iteration spaces. Inputs remain unchanged.
Repeated calls retain no inputs or outputs; independent destinations and shared
read-only inputs can be used concurrently. Earlier owned outputs survive later
calls.

Existing `validateTensorType`, `validateDestination`, `NormalizeAxis`,
`checkedProduct`, and `checkedMultiply` remain the shared validation foundation.
New private `activationFloat32Into` is the copying elementwise adapter;
`softmaxFloat32Into` accepts already validated nonempty geometry. Neither is a
new public interoperability or storage contract.

Two differences from the pinned evaluator are directly tested and documented:

- ReLU preserves the existing library's positive-zero result for NaN, while
  the reference returns NaN. Negative zero also maps to positive zero.
- Empty Softmax axes are successful empty no-ops by this tensor contract;
  the pinned evaluator rejects a zero-length maximum reduction. Two fixture
  entries retain that rejection explicitly rather than claiming agreement.

Softmax slices containing NaN, positive infinity, or only negative infinities
produce NaNs throughout that slice, matching the pinned nonempty cases.
Finite slices containing negative infinity give it zero probability. Different
logical slices remain independent, including noncontiguous middle-axis slices.
No special-value uniform fallback is added.

runtime budgets must include these allocations. NN-13 owns measured workspace
or interoperability changes after its runtime dependency exists. There is no
in-loop cancellation, integer activation, strided public view, schema default,
or general ONNX-conformance claim. RT-01 still owns the runtime's compatibility
profile and must account for the documented reference differences.

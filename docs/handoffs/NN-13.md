## Existing ownership and copying boundary

The preceding [tensor contract](../tensor-design.md) and
[matrix-product handoff](NN-05.md) continue to apply:

- `Tensor` owns private contiguous float32 or int64 storage. Constructors,
  `Shape`, typed value accessors, and `Clone` copy their inputs or results.
  There is no public borrowed mutable slice or generic storage escape hatch.
- `Into` outputs belong to callers. Destinations must have the checked shape
  and type and must not share storage identity with inputs, including shallow
  copies and empty values. Shared inputs and initializers are read-only by
  contract; callers synchronize any writes.
- `matrixProductValues` copies nonempty blocks into existing matrices and
  obtains copied matrix results. Batched MatMul also uses call-local output
  storage before the final destination copy. Matching-shape Add/Sub/Mul and
  the elementwise activation adapters likewise copy through existing matrices.
  Dynamic weights and constant weights use the same correctness path.
- Scratch and temporary matrices belong to an invocation. No mutable global
  workspace, public reusable workspace object, packed-weight cache, or
  cross-session storage reuse was introduced. `internal/device` is not exposed.
  Matrix host/device coherence and Metal behavior are untouched by this task.
- Numerical and output-lifetime tests of these primitives are available, but
  they are not a substitute for a runtime's value liveness and session tests.
  [RT-01/RT-08][runtime-roadmap] still own runtime resource budgets, immutable
  constants, session state, and returned-output ownership. Kernels have no
  in-kernel cancellation API.

## Resume criteria and benchmark plan

Resume NN-13 when an accessible RT-12 source revision and handoff supply a
working runtime, reproducible MLP and shape-heavy fixtures, named inputs and
expected outputs, and a way to run both graphs for at least two batch sizes.
Record the exact runtime and neuralnetwork revisions and how the runtime
resolves this backend. NN-13 does not implement RT-12 or require RT-16 to finish
first; its measurements provide an input to later RT-16 work.

1. Establish an unchanged copying baseline before altering ownership. Record
   model/input hashes, fixture provenance, batch sizes, Go version, OS/CPU,
   build tags, cgo status, `GOMAXPROCS`, and reference/runtime thread settings.
   Separate loading, first inference, and warmed inference; keep fixture setup
   outside timed sections and report repeated samples with exact commands.
2. Measure latency, allocations/op, and allocated bytes/op using Go benchmark
   reporting. Count actual copied payload bytes at bridge/transform boundaries
   in the benchmark instrumentation. Track simultaneously live values and
   workspace, including constants, destinations, matrix copies, and call-local
   buffers; distinguish this peak from cumulative allocated bytes or heap
   reservation, and cross-check allocation profiles. Do not report absent
   accounting as zero.
3. Use those measurements to select the smallest useful change: an internal
   contiguous float32 bridge, call/session-owned reusable workspace, or optional
   immutable-weight packing. Define read-only/writable access and alias
   lifetimes before implementation, keep the copying fallback, and avoid
   exposing initializer slices or `internal/device`. Retain changes only with
   demonstrated benefit or an explicit measured memory objective.
4. Run the same graphs and metrics after the change under the same conditions.
   Report before/after allocations, copied bytes, latency, and peak live memory
   without setting a universal zero-allocation or speedup requirement.
5. Verify reference outputs and shape-subgraph integer precision, retained
   outputs across later runs/close, unchanged weights, independent concurrent
   sessions, changing batch sizes, and relevant failure/cancellation cleanup.
   Run normal, `purego`, cgo-disabled, and race checks. Exercise Metal coherence
   on supported hardware only if the implementation touches that path; record
   an unavailable check explicitly. Keep runtime-only liveness work in RT-16.

Exact benchmark APIs/packages depend on the missing runtime handoff. No
unimplemented runtime method or benchmark command is presented here as usable.

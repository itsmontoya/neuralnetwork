## Ownership and mathematical contract

Every numerical input/output is float32. Shapes and axes use concrete int64
values. Reduction axes are explicit, normalized against input rank, and
distinct; duplicate positive/negative spellings are rejected after normalization.
Keep-dimensions replaces each reduced dimension with one; otherwise those axes
are removed. Reducing all axes of a nonscalar produces a scalar. An empty axes
list is a bit-preserving identity copy, including scalar input; scalars reject
every nonempty axes list. Pow uses trailing-axis multidirectional broadcasting.
Unary operations preserve shape, including scalars and zero dimensions.

Shape planning allocates no numeric payload. All input/type/axis/output-size,
destination shape/type/storage-identity, and used stride/product checks precede
the first write. Destination aliases are rejected even for identities and empty
values, including shallow Tensor copies. Returned errors leave destination
metadata and values unchanged. Inputs, axes, shapes, and statistics are never
mutated or retained. Repeated read-only Pow operands are allowed.

Outputs belong to callers and survive later calls. Shared immutable inputs may
be read concurrently with disjoint destinations. Reduction scratch consists
only of call-local axis/stride metadata; no mutable global state, retained
scratch, public workspace, view, optimizer, gradient, or backward cache exists.
No new dependency or runtime integration is introduced.

Zero-element outputs succeed after full validation and skip unused reduction
products/strides. Nonempty zero-count outputs are positive zero for sum, NaN for
mean, and negative infinity for max. Thus removing a zero axis may produce
nonempty identities; output-size overflow still fails during planning. Every
input dimension is checked even if another dimension is zero. Huge unused
iteration spaces can remain unnecessary for empty outputs.

Nonempty sums/means accumulate in row-major float32 order; means divide by the
resolved reduction count converted to float32. Input NaNs propagate to their
logical output, including noncontiguous axes. Max keeps the first equal value
in its row-major traversal; zero-tie signs are not promised across backends.
Nonempty reduction rounding and NaN payloads are not bitwise guarantees.
Finite fixture comparisons use `atol=rtol=1e-5`, NaN classification, and exact
infinity signs. Empty sum positive zero is checked exactly.

Unary math and Pow use existing `internal/f32` wrappers around standard-library
math, returning float32 results. Negative logarithms/square roots yield NaN;
log of either zero sign is negative infinity, sqrt preserves negative zero,
and exp of negative infinity is positive zero. Pow follows standard-library
special cases, including negative-zero odd powers, zero negative powers,
`NaN**0 == 1`, and `1**NaN == 1`. Floating domains produce values rather than
returned errors. Literal and reference tests check selected signed-zero cases
exactly, without promising NaN payloads or a universal numerical error bound.

## Shared helper reuse

- `reductionShape` combines checked output planning and normalized axes.
- `reduceFloat32Into` validates, handles identity/empty paths, and runs the
  selected reduction. `reductionStrides` only runs for nonempty input/output;
  it maps unreduced axes onto checked output strides before writes.
- `initializeReduction` and `reduceValuesInto` receive already validated
  geometry and the private operation constants.
- `mathFloat32Into` performs shared unary validation and writes values.

These are operation-local helpers. They reuse shared `normalizeAxes`,
`ValidateShape`, `checkedProduct`, `contiguousStrides`, `validateTensorType`,
and `validateDestination`. Pow reuses `binaryFloat32Into` and its broadcast
planning rather than duplicating arithmetic or expanding operands. Metadata
offset multiplications are bounded by the prevalidated payload lengths.

## References and runtime boundary

Ninety-nine original fixtures use independent NumPy reductions/vectorized math
and all agree with ONNX 1.16.2 ReferenceEvaluator. Generation tools are Python
3.9.6, NumPy 1.26.4, ONNX 1.16.2, and protobuf 4.25.3, available during
development at `/private/tmp/neuralnetwork-onnx-reference/bin/python`.
Ordinary Go tests read checked-in JSON without Python or a runtime library.
Fixture SHA-256:
`165660321fe5c25f792562b57b547165b1ff9474352826e102e3295562d0a0fc`.

Reduction reference models use IR 8/opset 18, selecting ReduceSum-13,
ReduceMean-18, and ReduceMax-18. They set `noop_with_empty_axes=1`; identity
models omit the optional axes input, while nonempty axes are explicit int64
tensors. This adapter expresses the already resolved mathematical operation.
Exp/Log/Sqrt/Pow models use IR 8/opset 13, selecting schema 13 for each.
The fixture README links exact pinned reference sources. NumPy max uses
`initial=-inf` to express the pinned float32 empty identity. Literal tests
independently verify sums `[30,48]`, means `[5,8]`, maxima `[9,12]`, all-axis
scalar results, empty identities, and signed-zero/domain rules.

The runtime still owns schema-specific axes inputs/attributes, omitted-axis
defaults, noop policy, profiles, shape metadata, and diagnostics. These fixtures
do not expand the initial runtime profile or implement RT-19 adapters. Integer
arithmetic, approximate activations, transformer coverage, public workspaces,
and in-kernel cancellation are outside NN-12.
